## 🔧 Corrección CORS / Registro (2026-07-29 sesión tarde)

### Diagnóstico / 诊断

| Hallazgo | Resultado |
|---|---|
| CORS middleware en backend | ✅ `allow_origins=["*"]` — correcto |
| Headers CORS en respuestas 200/201 | ✅ Presentes |
| Headers CORS en errores 422/500 | ✅ Presentes (verificado con curl.exe) |
| Registro con datos válidos | ✅ 201 |
| Procesos viejos/duplicados | ⚠️ PID 30728 (backend) + PID 43088 (frontend) — posible estado corrupto |

**Causa raíz probable**: procesos acumulados en los puertos 8000/5173 tras múltiples reinicios, causando que el navegador viera respuestas inconsistentes. El usuario NO debía ver error CORS porque el backend SÍ responde con headers correctos.

### Solución aplicada / 应用的解决方案

**Mejor práctica**: configurar **proxy de Vite** para que el frontend haga solicitudes al mismo origen, eliminando CORS por completo en desarrollo.

1. **`frontend/vite.config.js`**: agregado bloque `server.proxy`:
   ```js
   server: {
     proxy: {
       '/api': {
         target: 'http://127.0.0.1:8000',
         changeOrigin: true,
         secure: false,
       },
     },
   },
   ```

2. **`frontend/src/api/cliente.js`**: cambiado `URL_BASE` por defecto de `"http://127.0.0.1:8000"` a `""` (URL relativa). En producción se sigue usando `VITE_URL_API`.

3. **Limpieza de procesos**: matados PIDs viejos (30728, 43088) y reiniciados backend + frontend limpiamente.

### Resultado / 结果

- ✅ Registro funciona vía proxy: `localhost:5173/api/auth/registro` → proxy → `127.0.0.1:8000/api/auth/registro`
- ✅ CERO problemas de CORS en desarrollo
- ✅ Para producción: configurar `VITE_URL_API` en `.env` del frontend

## 🔧 Scripts de inicio fácil / 一键启动脚本

**Problema**: `uvicorn` no está en el PATH del sistema, causando que el usuario no pueda reiniciar el backend.

**Solución**: 3 scripts `.bat` en la raíz del proyecto:

| Script | Función |
|---|---|
| `iniciar_backend.bat` | 🖥️ Inicia FastAPI en puerto 8000 (limpia puerto antes) |
| `iniciar_frontend.bat` | 🌐 Inicia Vite en puerto 5173 (limpia puerto antes) |
| `iniciar_todo.bat` | 🚀 Inicia AMBOS en ventanas separadas |

> **Uso**: doble clic en `iniciar_todo.bat` → esperar 5 segundos → abrir `http://localhost:5173`

Los scripts usan `python -m uvicorn` (que SÍ funciona en el sistema) en lugar de `uvicorn` (que NO está en PATH). También matan procesos viejos automáticamente.

### 🔑 Nota importante sobre puertos / 端口重要提示

Al ejecutar `npm run dev`, si 5173 está ocupado, Vite salta a 5174.
**Para forzar 5173**: cerrar TODAS las terminales y ejecutar:

```powershell
# Limpiar puertos
Get-NetTCPConnection -LocalPort 5173,5174,8000 | Where-Object State -eq Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
# Iniciar backend
cd backend; uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
# Iniciar frontend (en otra terminal)
cd frontend; npm run dev
```

**CORS**: ahora en desarrollo se usa proxy Vite (sin CORS). En producción, configurar `VITE_URL_API` y usar `allow_origins` restrictivo en `main.py`.
