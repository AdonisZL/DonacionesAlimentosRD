# 01 — 需求规格

> 原始来源：[Descripcion.md](../../Descripcion.md)。本文件为需求的中文整理，与 [docs/es/01-requisitos.md](../es/01-requisitos.md) 对应。

## 1. 目标

### 总目标
设计并开发一个食品捐赠管理 Web 系统，能够登记、组织并分配剩余食物，借助物流优化算法（FEFO + 地理定位），符合多米尼加法规，以减少浪费、增强食品安全。

### 具体目标
- **OE1**：在中央数据库中登记并组织捐赠者、接收方和食物银行。
- **OE2**：实现按剩余保质期索引的动态库存模块（FEFO）。
- **OE3**：半自动匹配（确定性引擎 FEFO + PostGIS + 约束条件），由 Gemini AI 辅助，且必须人工确认。
- **OE4**：生成捐赠、库存与分配报表（透明度与税务优惠）。
- **OE5**：访问控制（RBAC）与数据保护（安全认证与角色管理）。

## 3. 功能需求（RF）

### 模块 1 — 注册与认证
- **RF-01**（高）：捐赠者注册：(a) 正式捐赠者（RNC、公司名称）；(b) 特殊/农业捐赠者（身份证/护照）。两者均需：邮箱、加密密码、地址、坐标。
- **RF-02**（高）：接收组织注册（RNC、检察院登记、容量、服务人群）。
- **RF-03**（高）：食物银行注册（场所、冷藏容量、营业时间）。
- **RF-04**（高）：邮箱/密码认证，签发 JWT，bcrypt 成本 ≥ 12。
- **RF-05**（中）：邮件找回密码（链接 15 分钟有效）。
- **RF-06**（高）：操作前需邮箱验证。
- **RF-07**（中）：编辑个人资料（联系方式、地址、地理定位）。
- **RF-08**（中）：账号逻辑注销（保留历史，Ley 11-92）。

### 模块 2 — 库存与 FEFO
- **RF-09**（高）：登记批次（产品、类别、数量、单位、到期日、厂商批号、存储条件）。
- **RF-10**（高）：自动分类易腐性（非易腐、半易腐、易腐、冷冻）。
- **RF-11**（高）：计算窗口 `到期日 − 今天` 并校验最小阈值。
- **RF-12**（高）：按到期日升序 FEFO 排序。
- **RF-13**（高）：临期（≤ 3 天）在平台和邮件预警。
- **RF-14**（高）：`窗口 ≤ 0` 时自动拒收。
- **RF-15**（中）：手动调整库存（仅食物银行），必须填写原因。
- **RF-16**（高）：不可变的移动历史（日志）。

### 模块 3 — 匹配
- **RF-17**（高）：用 PostGIS 按可配置半径查找兼容接收方。
- **RF-18**（高）：Gemini 辅助生成说明（温度 0.0，不改变确定性结果）。
- **RF-19**（高）：人工确认匹配。
- **RF-20**（中）：接收方拒绝或超时未取时重新分配。
- **RF-21**（高）：确认时通知捐赠者与接收方。
- **RF-22**（低）：反馈（1–5 评分与评论）。

### 模块 4 — 报表
- **RF-23**（高）：按周期的捐赠报表（筛选：日期、捐赠者、类别、状态）。
- **RF-24**（高）：当前库存报表（FEFO 顺序）。
- **RF-25**（高）：已完成分配报表（含凭证）。
- **RF-26**（高）：导出到 Google Sheets（API v4）。
- **RF-27**（高）：DGII 税务报表，不可变签名 PDF（Norma 04-2014，Art. 287 Ley 11-92）。

### 模块 5 — 安全与管理
- **RF-28**（高）：RBAC（捐赠者、接收方、食物银行、管理员）。
- **RF-29**（高）：审计（谁、做了什么、何时、IP）。
- **RF-30**（高）：10 分钟内 5 次失败则锁定。
- **RF-31**（高）：保存前记录数据同意（Ley 172-13）。
- **RF-32**（中）：管理面板（救助公斤数、有效率、按易腐性分布）。

## 4. 业务规则（RN）— 摘要

- **RN-01/02/03**：法人捐赠者必须有 RNC；接收方须具法人资格；每个用户/邮箱仅一个角色。
- **RN-04/05/06**：拒收过期批次；各类别最小窗口（非易腐 30–90、半易腐 15–30、易腐 1–5、冷冻 30–60 天）；FEFO 优先。
- **RN-07/08/09**：冷链；批次唯一且不可变标识；损耗须含原因 + 责任人。
- **RN-10/11/12/13/14**：初始半径 25 km（试点最大 35 km，上限 75 km）；不超接收方容量；最长 48 小时取货；不歧视；接收方确认收货。
- **RN-15/16/17**：保存 10 年；月度税务附表（Norma 06-2018）；税务报表不可变（须显式更正件）。
- **RN-18/19/20**：事先同意（Ley 172-13）；ARCO 权利 ≤ 15 个工作日；RBAC 且记录理由。

## 5. 非功能需求（RNF）— 关键指标

| RNF | 指标 |
|---|---|
| RNF-01 | 95% 的 GET ≤ 1.5 秒（100 并发用户） |
| RNF-02 | 批次登记 ≤ 2 秒 |
| RNF-03 | ≥ 50 万批次，FEFO 排序退化 ≤ 10% |
| RNF-04 | AI 超时 ≤ 12 秒；确定性引擎独立运行 |
| RNF-05 | 导出 ≤ 1 万行到 Sheets ≤ 10 秒 |
| RNF-06 | 月可用性 ≥ 99.5% |
| RNF-07 | RTO ≤ 4 小时，RPO ≤ 24 小时；每日加密备份 |
| RNF-08 | 首次捐赠 ≤ 5 分钟；SUS ≥ 70 |
| RNF-09 | ≥ 90% 页面达 WCAG 2.1 AA（axe-core） |
| RNF-10 | 默认西班牙语；预留英语（i18n） |
| RNF-11 | TLS 1.2+（SSL Labs 评级 A） |
| RNF-12 | bcrypt 成本 ≥ 12；RNC/身份证配 RBAC + 磁盘加密 |
| RNF-13 | 零高危/严重漏洞（OWASP ZAP） |
| RNF-14 | 符合 Ley 172-13（同意 + ARCO） |
| RNF-15 | 密码 ≥ 10 位（含大写、数字、符号） |
| RNF-16 | 单元测试覆盖 ≥ 80%，集成 ≥ 60% |
| RNF-17 | 模块化（轻量 DDD）；SonarQube A 级 |
| RNF-18 | 多浏览器；360 px 起响应式 |

## 6. 范围

**包含**：注册/认证、FEFO 库存、规则匹配、报表、安全/RBAC。
**排除**：实体物流/运输、货币交易、外部 ERP 集成、需求预测（SARIMA/LSTM/随机森林——仅概念分析，不实现）。
